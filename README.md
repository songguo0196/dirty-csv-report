# 脏 CSV 清洗与记账分析

## 这是什么

读取一份带脏数据的记账 CSV，清洗后算账，最终生成一份给人看的分析报告。

## 它解决什么问题

真实导出的记账数据不干净，直接拿来统计会算错或者直接崩。这份数据里实际存在这些问题：

| 脏在哪 | 不处理会怎样 |
|---|---|
| 第一行是表头 | 被当成一笔账记进去，金额转换直接报错 |
| 中间有空行 | 同样被当成一笔账，解析出 1 列，报错 |
| 金额带「元」字（`25元`） | `float("25元")` 抛 `ValueError`，整条程序停在这一行 |
| 金额是空的（`电影,,`） | 同上 |
| 金额是负数（`退款,-10元`） | **这不算脏数据，必须保留** —— 过滤掉会把总支出算错 |
| 文件是 GBK 编码 | 按 utf-8 读直接抛 `UnicodeDecodeError`，一行都读不出来 |

如果不做处理，这份数据既不能统计也不能用；而且报错会指向"转换失败"的那一行，看不出真正的原因是数据本身有问题。

## 怎么跑

```bash
python analyse.py
```

**要求**：Python 3.8 以上，只用标准库，不需要 pip 安装任何东西。

**输出**：`data/数据分析报告.txt`（终端里也会打一遍主要结果）

## 输入数据的格式

```
日期,项目,金额
2026-03-01,午饭,25元
```

三列：日期、项目、金额。**金额可能带「元」字，也可能是负数（退款）。**

## 输出长什么样

```
记账分析报告
================================================

数据来源：记账数据.csv
生成依据：收下7笔，跳过1行

跳过明细：
 第 8 行 '2026-03-03,电影,,' —— 金额看不懂：''

总支出：1370.0元
平均每笔：195.71428571428572元
最贵一笔：房租 1200.0元
```

**报告里会写明"收下几笔、跳过几行、分别是什么原因"** —— 因为只给结论不说数据来源和损失，读的人没法判断这个结论可不可信。

## 它能处理哪些脏数据

| 情况 | 怎么处理 |
|---|---|
| 表头行 | 跳过，不算错误 |
| 空行 | 跳过，不算错误 |
| 金额带「元」 | 摘掉「元」再转数字 |
| 金额是空的 | 跳过该行，记进「跳过明细」 |
| 金额不是数字 | 跳过该行，记进「跳过明细」 |
| 列数不够 | 跳过该行，记进「跳过明细」 |
| 文件是 GBK 编码 | 打印提示，返回空列表，不崩 |
| 文件不存在 | 打印提示，返回空列表，不崩 |
| 账本里一笔有效数据都没有 | 报告照常生成，但写明「本次没有数据，无法计算」 |

`data/记账数据_旧电脑导出的.csv` 是同一份数据的 GBK 版本（从旧电脑导出），内容与 `记账数据.csv` 完全一致，只是编码不同。它用来验证程序遇到编码不匹配时不会崩。

## 已知局限

- 只支持逗号分隔，不支持 Excel 的 `.xlsx`
- 不支持引号里带逗号的字段（例如 `"北京, 朝阳"`）
- 编码写死了 `utf-8`，遇到 GBK 只提示不自动重试
- 没有单元测试
- 「最贵一笔」把负数退款也算进去了，没有区分"支出最大"和"数值最大"

## 我用它学到的一件事

**算法错了会报错，数据错了会让正确的算法算出看起来很合理的错答案。**

调试时先看数据从哪来，再看算法怎么写 —— 因为前者不报错。
